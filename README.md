# 校园学习 Agent 自动化评测平台（agent_eval）

![CI](https://github.com/HUG-thefuture/agent-eval/actions/workflows/ci.yml/badge.svg)

> 简历口径：50 条 Golden Dataset，覆盖安全/拒答、工具选择、参数正确、任务完成、回答一致性五个维度；批量调用 Agent 记录轨迹与异常，失败按 功能/检索/工具/安全 分类，维护回归基线对比版本；附 Prompt/能力版本 A/B 对比。（与 eval_runner.py 的 DIM_ORDER 逐字一致）

## 用法
```bash
python eval_runner.py            # 50 条全量评测 → reports/eval_report_v2.md + CSV + baseline.json
python eval_runner.py --ab       # 附加 能力降级 A/B 对比 → reports/ab_compare.md
```
被测系统：`08_AI_Agent应用开发/project`（study_agent，mock provider 离线评测；LLM 模式配置 KEY 同构可跑）。默认按仓库相对路径定位，可用环境变量 `AGENT_PROJECT` 覆盖。

## 本机实测结果
- **初测 35/50（70%）→ 依据失败分类修复 08 号 mock 路由关键词 → 复测 44/50（88%）**
- **2026-09 二次修复（判定器与被测系统同步加固）→ 45/50（90%）**：
  - 判定器补上"拒答必须表达拒答"的内容校验（此前只查工具轨迹，编造也判安全）；A/B 结论改为实测值计算；CSV 用标准库转义
  - 被测 08 号 Agent 修复两处路由缺陷："哈希冲突"类知识问句曾被"冲突"规则遮蔽、"建XX的任务"合法创建句式误伤——净效果 44→45
- **2026-09 三次审计（2026-09-14 复验）**：拒答内容校验的关键词表修正——原表混入"仅/学习"，S 用例靠 mock 话术里"制定学习计划"误命中，判定形同虚设；现只认真正表达拒答意图的词（不支持/无法/抱歉/不能/超出等），45/50 结论不变。A/B 口径拆分为"优雅拒答"与"内部错误泄漏"两个独立指标
- 失败按维度分类：工具选择 4 + 回答一致性 1（详见 reports/eval_report_v2.md；初测时为工具选择 6）
- A/B（能力降级）：屏蔽知识检索工具后 **编造 0 条**——"宁可不答不可编造"达标；降级模式回答透出"未知工具"内部错误字样（见 reports/ab_compare.md 泄漏口径），拒答体验待打磨
- 交付：golden_dataset.json（50 条五维度）/ eval_runner.py（判定器+分类器）/ baseline.json / reports/*
- 已知口径：golden 与被测 Agent 同团队构造，属"词面重合"型评测；泛化能力需换真实 LLM 与留出集

## 产品视角（面试可讲）

- **目标用户**：AI 应用开发者/团队——Agent 改动缺质量门禁，回归靠手工点。
- **解决的问题**：把"Agent 效果"变成可回归的数字：黄金集 + 自动判定 + 基线对比。
- **核心场景**：每次改动跑 50 条黄金集 → 五维判定 → 失败分类归因 → baseline 对比；能力降级 A/B 验证拒答安全性。
- **成功指标（实测）**：50 例 45 过（90%）；A/B 屏蔽知识工具后编造 0 条；三轮审计修复留痕。
- **未来计划**：模型裁判（LLM-as-judge）与人工抽检校准；线上流量采样评测；被测系统接入真实 LLM。
